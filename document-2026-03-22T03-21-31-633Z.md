## 1. User Authentication Features

### Login

#### Usecase Diagram
```mermaid
graph TD
    User["User"]
    subgraph "System"
        UC1("Login")
    end
    User --> UC1
```

#### Sequence Diagram
```mermaid
sequenceDiagram
    participant User
    participant Frontend
    participant Backend
    participant Database

    User->>Frontend: Enter email and password
    User->>Frontend: Click Login button
    Frontend->>Backend: Send POST /api/auth/login with (email, password)
    Backend->>Database: Find user with email
    alt User exists and password is correct
        Database-->>Backend: Return user information
        Backend-->>Frontend: Return JWT token and user info
        Frontend->>User: Redirect to main page
    else User does not exist or password is wrong
        Database-->>Backend: Return null or error
        Backend-->>Frontend: Return 401 Unauthorized error
        Frontend->>User: Display error message
    end
```

#### Activity Diagram
```mermaid
graph TD
    Start((Start)) --> B{Open Login Page};
    B --> C[Enter email and password];
    C --> D[Click Login button];
    D --> E{Check credentials};
    E -- Valid --> F[Create session/token];
    F --> G[Redirect to main page];
    G --> End((End));
    E -- Invalid --> I[Display error message];
    I --> C;
```

```mermaid
graph TD

        UC2("Register")
    end
    User --> UC2
```

#### Sequence Diagram
```mermaid
sequenceDiagram
    participant User
    participant Frontend
    participant Backend
    participant Database

    User->>Frontend: Enter registration info (name, email, password)
    User->>Frontend: Click Register button
    Frontend->>Backend: Send POST /api/auth/register with (name, email, password)
    Backend->>Database: Check if email already exists
    alt Email does not exist
        Database-->>Backend: Confirm email is valid
        Backend->>Database: Create new user
        Database-->>Backend: Return created user info
        Backend-->>Frontend: Return success message
        Frontend->>User: Redirect to Login page
    else Email already exists
        Database-->>Backend: Report email exists
        Backend-->>Frontend: Return 409 Conflict error
        Frontend->>User: Display "Email already exists" error message
    end
```

#### Activity Diagram
```mermaid
graph TD
    Start((Start)) --> B{Open Register Page};
    B --> C[Enter personal information];
    C --> D[Click Register button];
    D --> E{Email exists?};
    E -- No --> F[Save user info to DB];
    F --> G[Display success message];
    G --> H[Redirect to Login Page];
    H --> End((End));
    E -- Yes --> J[Display error message];
    J --> C;
```

### Forgot Password

#### Usecase Diagram
```mermaid
graph TD
    User["User"]
    subgraph "System"
        UC4("Forgot Password")
    end
    User --> UC4
```

#### Sequence Diagram
```mermaid
sequenceDiagram
    participant User
    participant Frontend
    participant Backend
    participant EmailService

    User->>Frontend: Click on "Forgot Password"
    User->>Frontend: Enter email
    Frontend->>Backend: Send POST /api/auth/forgot-password with (email)
    Backend->>Backend: Generate password reset token
    Backend->>EmailService: Send email with password reset link
    EmailService->>User: Send email
    User->>User: Open email, click the link
    User->>Frontend: Open reset password page with token
    User->>Frontend: Enter new password
    Frontend->>Backend: Send POST /api/auth/reset-password with (token, newPassword)
    Backend->>Backend: Validate token and update new password
    Backend-->>Frontend: Return success message
    Frontend->>User: Display message and redirect to Login page
```

#### Activity Diagram
```mermaid
graph TD
    Start((Start)) --> B{Open Forgot Password page};
    B --> C[Enter email];
    C --> D[Send request];
    D --> E{Email exists in system?};
    E -- Yes --> F[Send email with reset link];
    F --> G[User receives email and clicks link];
    G --> H{Open reset password page};
    H --> I[Enter new password];
    I --> J[Update password];
    J --> K[Display success message];
    K --> End((End));
    E -- No --> M[Display error message];
    M --> C;
```

#### Sequence Diagram
```mermaid
sequenceDiagram
    participant User
    participant Frontend
    participant Backend
    participant STTService as "Speech-to-Text Service"
    participant Database

    User->>Frontend: Select Speaking Practice feature
    Frontend->>Backend: Request GET /api/speaking/phrases
    Backend->>Database: Get sample sentences for practice
    Database-->>Backend: Return sample sentences
    Backend-->>Frontend: Send sample sentences
    Frontend->>User: Display sample sentence "Hello, how are you?"
    User->>Frontend: Click Record button and speak
    Frontend->>Frontend: Record audio
    User->>Frontend: Stop recording
    Frontend->>Backend: Send POST /api/speaking/submit with (audio, phraseId)
    Backend->>STTService: Send audio for recognition
    STTService-->>Backend: Return recognized text "Hello, how are you?"
    Backend->>Backend: Compare recognized text with original sentence
    Backend->>Backend: Calculate score (e.g., Levenshtein distance)
    Backend->>Database: Save result to SpeakingAttempts table
    Backend-->>Frontend: Return score and recognized text
    Frontend->>User: Display score and feedback
```

```mermaid

    H --> I{Server converts speech to text};
    I --> J{Compare with sample & grade};
```

#### Usecase Diagram
```mermaid
graph TD
```

```mermaid
    subgraph "User Management"
        UC_UM1("View user list")
        UC_UM2("View user details")

    end
    Admin --> UC_UM1
    Admin --> UC_UM2
    Admin --> UC_UM3
    Admin --> UC_UM4
```

#### Sequence Diagram (Example: Delete User)
```mermaid
sequenceDiagram
    participant Admin
    participant Frontend
    participant Backend
    participant Database

    Admin->>Frontend: Access User Management page
    Frontend->>Backend: Request GET /api/admin/users
    Backend->>Database: Get user list
    Database-->>Backend: Return list
    Backend-->>Frontend: Send user list
    Admin->>Frontend: Click Delete button for a user
    Frontend->>Backend: Send DELETE /api/admin/users/:id
    Backend->>Database: Delete user with corresponding id
    note right of Backend: Log action to Admin Audit Log
    Database-->>Backend: Confirm successful deletion
    Backend-->>Frontend: Return success message
    Frontend->>Frontend: Refresh user list on UI
    Frontend->>Admin: Display "Deletion successful" message
```

#### Activity Diagram
```mermaid
graph TD
    Start((Start)) --> B{Admin logs in};
    B --> C[Navigate to User Management page];
    C --> D[Display user list];
    D --> E{Select action};
    E -- View --> F[Display user details] --> D;
    E -- Edit --> G[Open edit form];
    G --> H[Save changes];
    H --> I{Update in DB} --> D;
    E -- Delete --> J[Confirm deletion];
    J --> K{Delete from DB} --> D;
    E -- Exit --> End((End));
```

### Admin Log

#### Usecase Diagram
```mermaid
graph TD
    Admin["Admin"]
    subgraph "Admin Log"
        UC_AL1("View action history")
        UC_AL2("Filter history by Admin or action")
    end
    Admin --> UC_AL1
    Admin --> UC_AL2
```

#### Sequence Diagram (View Log)
```mermaid
sequenceDiagram
    participant Admin
    participant Frontend
    participant Backend
    participant AdminAuditService
    participant Database

    %% Context: Another Admin action occurred previously %%
    Admin->>Frontend: Perform action (e.g., Delete User)
    Frontend->>Backend: Send DELETE /api/admin/users/:id request
    Backend->>AdminAuditService: Log action (logAction)
    AdminAuditService->>Database: Save log to AdminAuditLog table

    %% View Log Functionality %%
    Admin->>Frontend: Access Admin Log page
    Frontend->>Backend: Request GET /api/admin/audit-logs
    Backend->>Database: Get log list from AdminAuditLog table
    Database-->>Backend: Return log list
    Backend-->>Frontend: Send log list
    Frontend->>Admin: Display action history table
```

#### Activity Diagram
```mermaid
graph TD
    subgraph "Admin Action (any)"
        A((Start action)) --> B[Perform data modification]
        B --> C{Log action in Audit Log Table}
        C --> D((End action))
    end

    subgraph "View Log"
        E((Start)) --> F[System queries Audit Log Table]
        F --> G[Display list of logged actions]
        G --> H{Admin filters/sorts}
        H --> F
        G --> I((End))
    end
```
